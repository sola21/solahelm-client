# SolaHelm Client

Клиент для Windows и Android (Linux — следующим), в котором есть **оба ядра — sing-box и mihomo**.
Клиент сам выбирает ядро по конфигурации. Рассчитан в первую очередь на подписки панели
[SolaHelm](https://github.com/sola21/solahelm), но принимает любые конфиги sing-box и Clash Meta.

Двуязычный интерфейс (**Русский / English**), светлая и тёмная тема.

> English version: [README.md](README.md)

> **Статус: альфа.** Проверено на Windows 11 и Android 16; возможны ошибки — пишите в Issues.

> **Disclaimer.** Независимый проект сообщества, не связан с sing-box, mihomo, Clash или Hysteria. Названия
> ядер используются только чтобы сказать, какое ядро запускает ваш конфиг. Вы сами отвечаете за то, чтобы
> пользоваться им в соответствии с законами, которые к вам применимы.

## Скачать

Последняя версия — на странице [Releases](https://github.com/sola21/solahelm-client/releases/latest):

| Файл | Для чего |
|---|---|
| `SolaHelm-<версия>-windows-x64.zip` | Windows 10/11 x64, данные в `%APPDATA%\solahelm-client` |
| `SolaHelm-<версия>-windows-x64-portable.zip` | то же, но все данные в папке `userdata` рядом с программой |
| `SolaHelm-<версия>-android-arm64.apk` | Android 7.0+, почти все телефоны |
| `SolaHelm-<версия>-android-x86_64.apk` | эмуляторы Android и некоторые Chromebook |

Windows: распакуйте в любую папку и запустите `solahelm_client.exe`. Для режима TUN нужны права
администратора — клиент запросит их при подключении. Дальше клиент обновляется сам.

Android: установите APK (разрешите установку из этого источника), добавьте подписку, нажмите
«Подключить» и разрешите VPN.

## Возможности

- **Простой и расширенный режим.** При первом запуске клиент спрашивает, как удобнее: простой — одна
  кнопка, страна и выбор сервера; расширенный — всё остальное. Меняется в «Настройки → Интерфейс».
- **Страна и IP выхода:** после подключения на главном экране флаг и страна, через которую идёт трафик,
  и IP — скрытый до нажатия (`203.0.*.*`). Определяется через `ipwho.is` по самому VPN, отключается в
  настройках.
- **Два ядра в одном клиенте:** sing-box 1.14 и mihomo 1.19, ядро выбирается по формату подписки.
- **Подписки:** sing-box JSON, Clash/mihomo YAML и «универсальные» — список ссылок `hysteria2://`,
  `vless://`, `trojan://`, `tuic://`, `ss://`, `anytls://` …, обычный или в base64. Импорт файла и текста
  из буфера, трафик и срок из заголовков подписки, просмотр и правка профиля с проверкой ядром.
- **Режимы:** TUN (весь трафик устройства), системный прокси (Windows), только локальный порт.
- **Узлы:** группы, задержка, выбор узла, режим маршрутизации (правила / глобально / напрямую).
- **Правила:** свой список в синтаксисе Clash поверх профиля, сохраняется при обновлении подписки;
  быстрое правило из карточки соединения.
- **Соединения** с группировкой по процессу (Windows) или приложению (Android), закрытие соединений;
  **журнал** ядра.
- **Windows:** трей с меню (подключение, режим, узлы, подписки), закрытие в трей, автозапуск, тихий
  старт, горячая клавиша вкл./выкл., выход с сохранением VPN, автообновление, portable-версия.
- **Android:** плитка в шторке (вкл./выкл. VPN без открытия приложения), уведомление можно свернуть.
- **Настройки поверх профиля:** стек TUN, строгая маршрутизация, MTU, сети в обход туннеля,
  исключения системного прокси, порт, доступ из локальной сети, IPv6, уровень логов, свои DNS-серверы.

## Как устроено

```
┌──────────────── Flutter UI (app/) ────────────────┐
│ подписки · узлы · пинг · трафик · соединения      │
└───────┬───────────────────────────┬───────────────┘
        │ управление (HTTP+секрет)  │ Clash API — одинаковый у обоих ядер
┌───────┴──────── core/ (Go) ───────┴───────────────┐
│ daemon: /fetch /start /stop /status …              │
│ detect: формат конфига → какое ядро                │
│ convert: ссылки → конфиг mihomo                    │
│ engine.Manager: одно активное ядро                 │
│   ├─ sing-box 1.14.x (как библиотека)              │
│   └─ mihomo 1.19.x  (как библиотека)               │
└────────────────────────────────────────────────────┘
 Windows: solahelm-core.exe рядом с клиентом, связь по 127.0.0.1
 Android: gomobile .aar внутри приложения + VpnService (TUN fd)
```

Оба ядра собраны **в один Go-бинарник**: у mihomo свои форки quic-go/gvisor/sing под другими путями
модулей, конфликтов нет. Единственная правка: `replace` protobuf из `go.mod` mihomo не переносится —
его форк не компилируется вместе с sing-box, обычный protobuf работает.

Интерфейсу не нужно знать, какое ядро запущено: sing-box получает `experimental.clash_api`, mihomo —
`external-controller`, и дальше все запросы (`/proxies`, задержки, трафик, `/connections`, `/logs`)
одинаковые.

### Выбор ядра

| Вход | Ядро |
|---|---|
| JSON с `outbounds` / `inbounds` / `route` … | sing-box |
| YAML/JSON с `proxies` / `proxy-groups` / `rules` / `mixed-port` … | mihomo |
| Ссылки (`hysteria2://`, `vless://` …), обычные или base64 | mihomo: ссылки превращаются в конфиг mihomo |

Список ссылок становится полноценным конфигом mihomo (`core/convert`, парсер ссылок — сам mihomo):
группы `Proxy` (ручной выбор) и `Auto` (по задержке), DNS через туннель, TUN, локальные сети напрямую.
Ссылки, которые mihomo не умеет (Naive, MASQUE), пропускаются — карточка подписки это показывает.

### Windows

Клиент запускает `solahelm-core.exe serve` и общается с ним по loopback-HTTP с секретом. Ядро следит за
процессом клиента и останавливается, если тот пропал, — TUN и системный прокси не остаются висеть.
Системный прокси при включении запоминает прежние настройки WinINet и восстанавливает их при остановке.
TUN требует прав администратора: сам клиент работает без них, а ядро при необходимости перезапускается с
повышенными правами (один запрос UAC, при выключенном UAC — без запроса); при отказе клиент показывает ошибку.

«Выйти, оставив VPN включённым» (меню трея): ядро перестаёт следить за окном, адрес и секрет лежат в
`core/session.json`, следующий запуск клиента подхватывает ядро. Обновления: клиент проверяет последний
релиз этого репозитория, скачивает zip (через локальный порт ядра, если VPN включён) и
`install.ps1` распаковывает его поверх (папка `userdata` и `portable.txt` не трогаются).

### Android

- Ядра собраны в `solahelm-core.aar` (gomobile, пакет `core/mobile`) и работают внутри приложения — тот
  же управляющий сервис, что и `solahelm-core.exe`. Тег сборки `cmfa`, как в Clash Meta for Android:
  mihomo не пытается читать системный список пакетов.
- TUN открывает `VpnService` (`172.19.0.1/30`, `fdfe:dcba:9876::1/126`, DNS `172.19.0.2`), ядро получает
  готовый дескриптор. Само приложение исключено из VPN, поэтому соединения ядер не зацикливаются.
- Для sing-box — свой platform interface (`core/engine/singbox_android.go`): TUN из дескриптора, защита
  сокетов, текущая сеть от `ConnectivityManager` вместо netlink, DNS `local` через DNS-серверы настоящей
  сети, владелец соединения через `getConnectionOwnerUid`.
- Плитка в шторке (`VpnTileService`) включает VPN без интерфейса: ядро запоминает последний удачный
  запуск (`last-start.json`) и повторяет его; открытое приложение узнаёт об этом и обновляется.
- Без уведомления Android не держит VPN в фоне; в настройках его можно свернуть (канал с минимальной
  важностью) или отключить совсем в настройках Android.

### Правила и настройки

Правила хранятся отдельно от подписки, в синтаксисе Clash: `TYPE,PAYLOAD,TARGET[,no-resolve]`. Для
профилей mihomo список целиком заменяет правила профиля; для sing-box правила переводятся (DOMAIN*,
IP-CIDR, порты, PROCESS-*, RULE-SET, NETWORK, MATCH → final) и встают перед правилами профиля, сразу
после служебных sniff/hijack-dns. Ядро проверяет правила до сохранения.

Настройки «Подключение и TUN» и «Ядро» (`engine.Tuning`) применяются к обоим ядрам поверх профиля;
при изменении во время подключения появляется кнопка «Переподключить». Свои DNS-серверы (только профили
mihomo): `respect-rules`, удалённые резолверы через VPN, прямые — для VPN-серверов и прямого трафика.

## Сборка

Нужно: Go 1.26+, Flutter 3.x; для Windows — Visual Studio Build Tools (C++) и включённый «Режим
разработчика» (символические ссылки для плагинов Flutter); для Android — Android SDK, NDK r28, JDK 17 и
`gomobile` (`go install golang.org/x/mobile/cmd/gomobile@latest && gomobile init`).

```powershell
# Windows: два архива в dist\ (обычный и portable)
powershell -ExecutionPolicy Bypass -File tools\package-windows.ps1
```

```bash
# Android: два APK в dist/
bash tools/package-android.sh
```

Release-сборка Android подписывается ключом из `app/android/key.properties` (в git его нет); без него —
отладочным ключом. Релиз на GitHub: `tools\release.ps1` (сверяет версии в `pubspec.yaml` и
`appVersion`, публикует архивы и APK через `gh`).

Проверка:

```powershell
cd core
.\build.ps1 -Test          # тесты Go + bin\corectl.exe
.\bin\corectl.exe detect https://panel.example.org/<prefix>/sub/<token>/clash
.\bin\corectl.exe test   https://panel.example.org/<prefix>/sub/<token>/singbox
cd ..\app
flutter analyze; flutter test
```

`corectl test` запускает конфиг в режиме «только порт» (всё на 127.0.0.1), через Clash API меряет
задержку каждого прокси, показывает выбор групп и внешний IP, затем останавливается. Без
`solahelm-core` рядом (или с `--dart-define=DEMO=true`) приложение работает на демо-данных.

## Структура

- `core/engine` — обёртки над ядрами, `Manager` (одно ядро за раз), правила, настройки, Android-платформа.
- `core/detect` — распознавание формата и выбор ядра; `core/convert` — ссылки → конфиг mihomo.
- `core/daemon` — управляющий HTTP-сервис; `core/mobile` — API для Android (gomobile).
- `core/cmd/corectl` — консольная утилита и `solahelm-core.exe`: `detect`, `run`, `test`, `serve`, `version`.
- `app/` — Flutter-приложение: `lib/screens` — экраны, `lib/state` — состояние и настройки, `lib/core` —
  связь с ядром, `lib/l10n` — строки RU/EN; `android/` — VpnService, плитка, мост к ядру.
- `tools/` — сборка, упаковка, выпуск релиза.

## Что проверено

- Подписки SolaHelm (sing-box JSON, Clash YAML со встроенным шаблоном и обоими пресетами
  маршрутизации, универсальные ссылки) распознаются и стартуют в своём ядре; все прокси видны через
  Clash API.
- Windows 11: режимы «только порт», системный прокси (с восстановлением прежних настроек) и TUN для обоих
  ядер; остановка ядра при исчезновении клиента; выход с сохранением VPN; автообновление.
- Android 16 (arm64): универсальная подписка (mihomo) и JSON-подписка sing-box в режиме TUN — трафик идёт
  через VPN; подключение, отключение, переподключение; плитка при закрытом приложении; смена
  Wi-Fi ↔ мобильная сеть.
- Интеграционный тест `app/test/daemon_integration_test.dart` (нужны `SOLAHELM_CORE` и `SOLAHELM_SUB`) —
  подписка, запуск, узлы, пинг, выбор узла, трафик, остановка для обоих ядер.

## Известные особенности

- mihomo с DNS-настройками шаблона панели (DoH Cloudflare + `prefer-h3`) в TUN на Windows иногда отвечает
  с задержкой. Помогает «Свои DNS-серверы» в настройках ядра.
- mihomo держит `cache.db` открытым до конца процесса, поэтому его рабочая папка постоянная.
- Если порт из конфига занят другим клиентом, mihomo продолжает без этого порта.
- JSON-подписка sing-box из панели не содержит Naive, а ссылки содержат (mihomo их пропускает).
